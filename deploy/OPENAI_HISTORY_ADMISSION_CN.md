# OpenAI OAuth 历史请求准入

## 账号配置

OpenAI OAuth 账号默认开启“拒绝外部历史请求”，新老账号缺少字段时均按开启处理。在账号创建、编辑页面修改；批量编辑必须先勾选该项，且只允许选择凭据所属的 OAuth 母账号。影子账号继承母账号，不能独立放宽限制。

账号 `extra` 示例：

```json
{
  "openai_oauth_reject_external_history": true
}
```

仅显式 `false` 关闭此项限制。关闭不绕过用户/分组权限、模型能力、额度、HTTP 响应所有权或安全审核，也不保证任意上游旧响应均可续接。非 OAuth 账号不适用。

## 调度行为

- 首条新对话正常选号，新 session ID 尚未建立绑定不是拒绝理由。
- 开启限制的账号只接收已匹配到自身凭据身份的历史；未匹配或属于其他账号时，跳过当前候选。
- 当前候选拒绝后仍会尝试其他账号，关闭限制的账号可以进入原有处理流程。
- 候选耗尽且历史策略是排除可服务账号的原因时，提示“当前没有可接续此历史对话的账号，请新建对话后重试。”
- WebSocket 连接内不能安全换号时要求重连，重连后重新筛选账号，不直接要求清空对话。
- 策略拒绝不触发账号冷却；数据库故障返回服务错误，不伪装成外部历史。

## 错误请求记录

开启 Ops 监控时，历史准入失败进入“使用记录 → 错误请求”。普通 HTTP、已开始的 SSE 和 WebSocket 首轮/后续轮次均记录逻辑错误状态码及失败原因，不会因连接状态仍为 200/101 而漏记。策略拒绝归为本地路由限制，不算上游账号故障或可用性错误；记录不复制对话正文或长期归属数据。普通用户查看仍受“允许用户查看自己的错误请求”开关和用户隔离约束，计数请求沿用现有过滤规则。

管理端错误请求页默认的“错误”筛选排除业务限制；查看此类策略拒绝应选择“全部”或“排除项”。普通用户自己的错误请求列表包含此类失败。

## 长期记录

启动时的前向迁移增加 `openai_conversation_bindings`。该表只保存认证用户、标识哈希、账号及 OAuth 身份/共享作用域元数据，不保存聊天正文、工具参数、工具结果或访问令牌。

长期归属不设置闲置 TTL。现有 `sticky_session_ttl_seconds` 和 `sticky_response_id_ttl_seconds` 仍只控制短期缓存。只要长期记录未被删除，即使 Redis 被清理、进程重启或对话闲置数天，仍能匹配原账号，再检查其当前是否可用。

应将该表纳入正常 PostgreSQL 备份，并根据响应量监控表与索引容量。不得擅自添加按天清理任务，否则会破坏长期匹配保证。用户或账号软删除、物理删除时清理关联记录；临时限流、额度耗尽和普通 token 刷新不会清理归属。重新授权到不同上游身份或改变共享作用域后，旧记录不再作为当前身份的准入依据。

## 升级注意

调度精简快照必须保留此开关的有效布尔值。修复版本会将缺少该字段的旧 OAuth 快照视为缓存未命中，通过现有数据库回查与重建机制更新，不需要清空整个 Redis。账号原本关闭的设置不会被改成开启，也不会删除长期对话归属。

仍有效、用户所有权可验证的旧响应缓存可以在请求审核后补录。仅有旧的分组粘性缓存不能证明用户归属，不直接升级为长期记录。

升级前已经过期且没有可信记录的历史无法回溯恢复。默认开启可能使这些旧会话无法进入严格账号；可以新建对话，或由管理员明确关闭某个账号的限制后使用既有兼容能力。不要通过清理历史正文、遍历账号探测或重复执行工具来补录。

网关记得原账号，不代表 provider 仍保留原响应、WS 连接或加密状态。上游状态过期继续使用其原有错误或安全恢复语义，与本策略拒绝分开处理。

接口及错误约定见 [OpenAI Responses 协议](../docs/protocols/OPENAI_RESPONSES.md#oauth-history-admission)。
